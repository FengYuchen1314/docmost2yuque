# ADR-0002：统一搜索第一阶段采用 PostgreSQL

- 状态：Accepted
- 日期：2026-08-24

## 决策

第一阶段使用 PostgreSQL 17 的 `simple` 全文索引、`pg_trgm` 三元组索引和事务内搜索投影。保留 `search_documents` 作为统一索引契约；如果规模或中文召回质量超过 PostgreSQL 边界，可将相同投影异步复制到 Typesense 或 OpenSearch，而不改变领域表和 API。

## 原因

- 页面、发布、小记、模板、团队等数据可以与领域写入处于同一数据库事务，不产生“已保存但搜不到”的窗口。
- `pg_trgm` 对中文连续子串、英文前缀、路径和代码片段均有可预测表现；`simple` tsvector 补充英文词项和排名。
- 当前规模不值得为搜索额外引入一套高可用服务、租户隔离、备份和灾备链路。
- 统一授权服务必须对候选结果做最终过滤。搜索引擎本身只承担粗粒度 Workspace、可见性和资源类型过滤。

## 中文策略

- 中文精确词组与连续子串：`ILIKE` + GIN trigram。
- 英文、代码和中英混排：`simple` tsvector + trigram。
- 标题权重高于标签和正文；完全标题匹配最高。
- 拼音不通过不可审计的临时映射实现。后续若启用拼音召回，使用独立的、可重建 `search_terms` 字段和固定词典版本，并加入离线相关性评测。

## 权限边界

- 内部搜索默认只查草稿/规范资源，避免同一页面的草稿与发布结果重复。
- 公开搜索只查 `PUBLISHED + PUBLIC + active` 文档。
- 候选项在返回前逐项调用统一授权服务；无权标题、摘要、路径和匹配分数都不会进入响应。
- 页面取消发布时删除公开投影，不依赖前端隐藏。

## 迁移触发条件

出现以下任一条件时重新评估 Typesense/OpenSearch：单 Workspace 活跃索引超过 200 万文档；P95 查询超过 300 ms；中文离线 NDCG@10 长期低于目标；模糊/拼音/同义词需求无法由可维护的 PostgreSQL方案满足。
