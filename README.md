# 知序（docmost2yuque）

> 项目状态：已封存。仓库保留当前代码、测试和部署配置，但不再将现有版本描述为“完整复刻语雀”或“可以替代语雀的成品”。

## 这个项目是做什么的

知序是一套可自行部署的个人与团队知识协作平台，目标是提供接近语雀的知识库、文档编辑、结构化内容、分享发布和团队协作体验。

项目最初计划以 Docmost 的产品与工程实现作为参考，重新选择适合的技术架构，并系统复刻语雀的功能范围、页面结构和交互逻辑。当前仓库中的业务代码为独立实现，不是语雀源码，也没有继续照搬 Docmost 后端。

语雀和 Docmost 的名称、商标、界面及相关产品权利归各自权利人所有。本项目与其官方没有从属、授权或合作关系。

## 完成度如何理解

下面的“已完成”表示仓库中已经存在对应的数据模型、接口、页面或可运行链路，并不代表其功能深度、异常处理、视觉细节和生产可靠性已经与语雀完全一致。只出现页面外壳、基础接口或演示性交互的能力会列入“部分完成”，而不会算作完整实现。

## 已经完成

### 工程与部署基础

- Web 前端使用 Vue 3、Vuetify、Pinia、Vue Router、TanStack Query 和 Vite。
- 业务 API 与异步 Worker 使用 Java 25、Spring Boot 和 PostgreSQL，按领域模块拆分。
- 实时协作服务使用 Rust、Tokio 和 Yrs，实现 Yjs 协议接入、房间管理、持久化及内容回写基础链路。
- 提供 PostgreSQL、API、Worker、协作服务、Web 和 Nginx 的 Docker Compose 部署配置。
- 提供 GitHub Actions Web 构建、测试、镜像验证和可选部署流程。
- 当前版本曾完成生产构建与服务器预览部署；封存后不承诺预览服务持续可用。

### 账号、注册与实例管理

- 用户账号只使用邮箱，不提供独立用户名登录。
- 首次部署后由第一个进入初始化流程的用户使用邮箱创建实例管理员；该首次管理员不要求先完成邮箱验证。
- 默认使用邮箱加密码登录，同时提供邮箱验证码登录路径。
- 管理员可以选择关闭或开放公开注册；公开注册要求 SMTP 已配置并通过测试，同时要求邮箱验证。
- 无论公开注册是否开放，管理员都可以为指定邮箱创建邀请并发送邀请邮件。
- 已有密码重置、会话管理、登录限流、注册状态读取和 CSRF 防护基础实现。
- 管理后台已包含注册策略、SMTP 配置与测试、邀请管理和用户管理界面。

### 核心知识协作领域

- 工作区、成员、团队和用户组的基础管理。
- 知识库的创建、更新、归属、成员、分享、发布及生命周期基础接口。
- 多级目录、分组、链接节点、排序、移动和目录修订记录。
- 文档、白板、电子表格和数据表四类内容的创建、读取、保存及基础编辑界面。
- 文档附件、历史版本、属性、权限、分享和发布管理面板。
- ACL 授权模型及工作区、团队、用户组、知识库和页面层级的基础权限链路。
- 站内评论、收藏、消息、动态、最近编辑/浏览和协作者信息的基础能力。

### 内容分发与辅助模块

- 分享链接、密码访问、邀请访问、访问申请和分享快照的基础链路。
- 公开主页、知识花园、公开阅读器、公开发现和内容互动页面。
- 小记、模板、回收站、导入导出任务、内容统计和统一搜索的基础页面与接口。
- OAuth、开放平台、外部 API 和 MCP 接口的基础模块与管理页面。
- 本地附件存储、附件文本提取、后台任务和审计日志基础设施。

### 当前已经对齐的前端部分

- 已建立接近语雀的信息架构，包括工作台、知识库、目录、编辑器、设置页、公开阅读页和管理后台的主要路由。
- 文档编辑器已有标题、块内容、自动保存状态、目录面板、大纲面板、评论/引用入口、发布和分享入口。
- 文档插入菜单已实现搜索、分组、斜杠唤起和 17 类基础插入命令的统一注册机制。
- 最近一轮已按桌面端截图实测调整编辑器目录展开/收起、顶部栏、工具栏、标题区、正文区和大纲区的主要几何关系。
- 已修复旧浏览器环境下 `crypto.randomUUID is not a function` 导致文档、白板、电子表格和数据表无法打开的问题。

## 部分完成

### 文档编辑器

- 当前编辑器能完成基础块编辑、插入和保存，但还不是语雀级别的成熟结构化富文本编辑器。
- 工具栏只完成了一部分控件和几何对齐；格式刷、清除格式、字体与字号体系、完整颜色系统、列表与缩进、引用、公式、内联代码等仍未完整复刻。
- 多块选择、拖拽重排、嵌套块、复杂粘贴、跨块撤销重做、光标恢复、输入法边界、快捷键体系和右键菜单仍不完整。
- 评论锚点、引用关系、协作者光标和复杂内容块之间的精确联动仍未达到可替代语雀的程度。
- Markdown、HTML、Office 内容及外部网页复制进编辑器后的无损转换没有完成。

### 白板、电子表格与数据表

- 三类编辑器都有可运行的基础模型和界面，但更接近功能原型，而不是完整生产级编辑器。
- 白板缺少完整的多选、缩放变换、吸附与对齐、组合、图层、连接线编辑、图片与文件、快捷键、历史记录和多人协作体验。
- 电子表格缺少完整公式引擎、区域选择、批量复制粘贴、填充柄、格式系统、合并单元格、冻结、筛选、排序和大数据量性能优化。
- 数据表缺少语雀同等级的字段类型、字段配置、分组、条件组合、关联、公式、汇总、表单、自动化、权限和视图个性化能力。

### 协作、权限与发布

- 协作协议、服务和基础客户端连接已经存在，但文档实时协作目前只完整启用于单个、无标记的普通段落；富文档会关闭实时协作。
- 白板、电子表格和数据表目前主要将整段 JSON 作为 `Y.Text` 同步，还不是结构级 CRDT；前端只显示在线人数，没有远端光标和选区可视化。
- 所有内容类型的并发一致性、断线重连、离线恢复、长时间会话和大文档压力场景尚未完整验证。
- 权限、分享、发布和公开阅读已经有主要数据链路，但组合权限、继承冲突、匿名访问边界、链接失效和复杂成员变更尚缺系统性回归。
- 知识库外观、水印和目录策略目前仍以 JSON 配置为主，没有完成语雀式可视化配置体验。
- 邮件链路已有 SMTP 配置和测试能力，但没有完成对各类邮件服务商、退信、限频、投递监控和域名信誉的生产验证。

### 搜索、导入导出与开放能力

- 搜索目前基于 PostgreSQL `simple` 全文索引和 `pg_trgm`，已有统一搜索和重建接口，但没有拼音、同义词、语义或向量检索；中文主要依赖 trigram/子串，也没有大规模相关性与性能报告。
- 已有导入导出任务框架。当前导出范围主要是：文档到 Markdown、HTML、DOCX、PDF、JPG；白板到 PNG、JPG、SVG、PDF；电子表格到 XLSX、PDF；数据表到 XLSX、CSV。
- 导入入口可接受 Markdown、HTML、TXT、ZIP、DOCX、XLSX、Notion 和 Confluence 等来源，但复杂排版与结构的保真度没有达到原产品水平，也没有完成 Docmost 或语雀的全量无损迁移。
- OAuth、开放 API、MCP 等已有基础实现，但 API 稳定性、兼容版本、SDK、Webhook、重试、配额、审计和第三方生态没有完成。
- AI 写作页目前只是创建文档的入口，没有接入真实模型，也没有生成、流式输出、上下文引用、知识库检索或安全治理能力。

### 客户端与自动化门禁

- 当前可用形态是 Web/PWA；`clients/mobile`、`clients/browser-extension` 和 `clients/desktop/src-tauri/src` 没有可发布实现，移动端、桌面端和浏览器扩展尚未完成。
- GitHub Actions 当前主要执行 Vue 单元测试、前端构建和 Web 镜像冒烟，不会自动执行 Java 测试、Rust 测试、Playwright、VPS 端到端脚本或安全测试。
- 前端测试大量使用模拟 API，190 项通过只能证明其覆盖范围内的组件行为，不代表真实部署的全部业务链路已经验收。

## 为什么封存

“完整复刻”并不只是还原几个静态页面，而是需要覆盖一个持续演进产品的编辑器内核、所有业务域、隐藏状态、边界条件、跨端交互、多人协作、数据迁移、运维和安全体系。截图和有限的交互观察只能还原可见部分，无法可靠推断全部内部语义。

现有模型可以快速搭建大量页面、接口和测试，也可以逐批修正明显差异，但无法在当前条件下对“所有功能、所有操作逻辑、每个界面都一模一样”给出可信的完成保证。继续把页面数量或接口数量当作完成度，会让项目看起来庞大，却掩盖编辑器深度、交互一致性和生产可靠性上的缺口。因此暂时封存，保留已有成果与真实欠账，不再宣称已经完成 1:1 复刻。

- `collaboration/`：Rust 实时协作服务。
- `contracts/`：OpenAPI 与跨服务数据契约。
- `deploy/`：Docker Compose 和 Nginx 配置。
- `scripts/`：部署、冒烟及后端到端检查脚本。

## 构建与部署说明

`main` 分支上的 Web 变更会由 GitHub Actions 安装锁定依赖、运行单元测试、构建前端并验证容器。部署步骤默认关闭；只有手动触发工作流，或显式设置仓库变量 `DEPLOY_WEB_ON_PUSH=true`，才会更新服务器上的 Web 服务。数据库、API、Worker 和协作服务不会在仅 Web 部署时重建。

生产连接信息只能保存在 GitHub Environment Secrets 或服务器环境文件中，不应提交 `.env`、私钥、口令或服务器地址。现有工作流使用 `VPS_HOST`、`VPS_PORT`、`VPS_USER`、`VPS_DEPLOY_PATH`、`VPS_SSH_PRIVATE_KEY` 和 `VPS_KNOWN_HOSTS`。

## 使用提醒

- 当前代码适合继续研究、审计和二次开发，不适合在未完成安全与可靠性验证前承载重要生产数据。
- 如重新启动项目，应先确定可验收的功能边界，优先替换文档编辑内核，再按页面和交互状态建立截图基线与自动化视觉回归。
- 不应把当前仓库中的页面数量、接口数量或测试数量直接等同于产品完成度。
- 根目录尚未提供覆盖整个仓库的许可证文件；对外分发或接受贡献前，应先明确整体许可证和第三方参考边界。
